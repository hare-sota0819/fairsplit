# FairSplit 한글화 용어집

작성일 2026-08-05 · 대상: `src/messages/en.json` 473개 문구

## 0. 이 문서를 어떻게 읽나

번역을 시작하기 전에 **핵심 단어를 먼저 확정하려고** 만든 문서입니다. 473개를
먼저 옮겨놓고 나중에 단어를 바꾸면 전부 다시 손봐야 하기 때문에, 여기서 어긋나면
가장 비쌉니다.

원칙은 하나입니다. **영어를 한국어로 옮기지 않고, 같은 상황에서 한국 앱이 실제로
쓰는 말을 찾아서 씁니다.** 그래서 아래 표의 모든 항목에는 "어디서 실제로 쓰고
있는지" 근거가 붙어 있습니다. 근거를 못 찾은 항목은 숨기지 않고 §4에 따로
모아뒀습니다 — 그쪽이 진짜 결정이 필요한 자리입니다.

읽으실 때 봐주실 것은 두 가지입니다.

**2026-08-07로 §3·§4·§8이 모두 확정됐습니다.** 이 문서는 이제 고르는 문서가
아니라 번역이 따라야 할 기준입니다. 번역 중 판단이 갈리면 여기로 돌아옵니다.

## 1. 말투 — 해요체로 통일합니다

토스는 사내 어법 규정으로 **해요체를 강제**하고, 외부 개발자용 공식 문서에도
"제품 안의 모든 문구는 어떤 상황에서든 일관되게 `-해요`로 끝난다"고 못박아
두었습니다. 다른 앱들도 대체로 이쪽입니다.

중요한 건 **한 제품 안에서 섞지 않는 것**입니다. 안내문은 해요체인데 에러만
`~하십시오`로 튀면 그 순간 다른 사람이 쓴 것처럼 읽힙니다.

| 자리 | 형태 | 예 |
| --- | --- | --- |
| 안내·설명문 | 해요체 | 영수증을 찍어두면 나중에 편해요 |
| 에러 | 해요체 | 계좌를 찾을 수 없어요 |
| 버튼 | 명사 또는 명사+하기 | 저장 / 충전하기 |
| 폼 라벨 | 조사 없는 명사 | 이름, 이메일, 금액 |
| 화면 제목 | 명사 | 정산 현황 |

원문 영어가 이미 담백하고 사람 말투라(`Nothing recorded yet.`,
`Rounding always favours whoever paid.`) 해요체와 잘 맞습니다.

## 2. 문장 규칙

### 2.1 버튼

기본은 **명사**, 동작을 강조해야 하면 **명사+하기**입니다. 토스 계열 비평에서
지적하듯 `계정 생성하기`처럼 무조건 `하기`를 붙이면 쓸데없이 길어집니다.

| 원문 | 한국어 |
| --- | --- |
| Save | 저장 |
| Save expense | 지출 저장 |
| Add item | 품목 추가 |
| Create group | 모임 만들기 |
| Set up a wallet | 지갑 만들기 |

`생성`은 쓰지 않습니다 — 한국어 앱은 `만들기`를 씁니다.

### 2.2 확인 다이얼로그

토스 디자인 시스템의 규칙: **닫기 버튼을 "취소"라고 쓰지 않습니다.** 사용자가
"지금까지 한 작업이 날아가나?"로 오해하기 때문입니다. 그리고 실행 버튼은
`확인` 같은 뭉뚱그린 말 대신 **무슨 일이 일어나는지 그대로** 적습니다.

| | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| 안 됨 | 취소 | 확인 |
| 됨 | 닫기 | 삭제 |

이 규칙이 실제로 걸리는 자리를 하나 찾았습니다. 지출 취소 확인창이
`Cancel expense`(지출 취소) 옆에 `Cancel`(그만두기)을 나란히 놓는 구조라, 그대로
옮기면 **취소 옆에 취소**가 됩니다. 그만두는 쪽을 `닫기`로 쓰면 사라집니다.
(§4-C에서 이 화면 자체가 스위치로 바뀌지만, 규칙은 다른 확인창에도 그대로
적용됩니다.)

### 2.3 에러

토스가 공개한 원칙에서 이 앱에 그대로 적용되는 것들입니다.

- **책임을 묻지 않습니다.** `잘못 입력했습니다`가 아니라 `계좌를 찾을 수 없어요`.
- **다음에 뭘 하면 되는지 알려줍니다.** 에러 문구의 역할은 사실 통보가 아니라
  다음 화면으로 넘어가게 하는 것입니다.
- **`~해야 해요`보다 `~할 수 있어요`.** 같은 내용도 부정적 감정이 줄어듭니다.
- **`됐어요`보다 `했어요`.** 능동으로 씁니다.

### 2.4 빈 화면

한국 앱들은 "없습니다"로 끝내지 않고 **다음 행동을 붙입니다.** 배민은
`설정하신 주소에 맞는 결과가 없어서 비슷한 가게를 찾아봤어요`, 웨이브는
`검색결과가 없어요. 이런 검색어는 어떠세요?` 식입니다.

이 앱의 빈 화면 문구는 원문이 이미 이 구조입니다
(`No expenses yet — tap Add to record the first one.`). 구조를 지키면 됩니다.

## 4. 빌려올 말이 없는 것들 — 전부 확정됨 (2026-08-07)

조사하면서 확인된 사실입니다. **이 앱의 핵심 개념 몇 개는 한국 앱에 선례가
없습니다.** 트래블월렛·트래블로그·SOL트래블 전부 "거래별 환율"만 보여주고, "지금
내 지갑에 든 돈이 나한테 얼마에 온 것인가"라는 개념 자체를 다루지 않습니다.
정산 앱 쪽도 마찬가지로 환율을 아예 안 건드립니다.

즉 이 앱이 한국 시장에서 하려는 말이 새로운 말이라서, 베낄 데가 없습니다.
아래는 검토한 대안과 최종 선택이며, 왜 그렇게 정했는지까지 남겨둡니다.

### 4-A. "내가 실제로 환전한 단가" — **`내 환율`로 확정 (2026-08-07)**

지갑에 넣은 돈의 평균 원가입니다. 원문은 `your rate`, `wallet rate`,
`average cost`로 부릅니다.

| 안 | 표기 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A1 (추천)** | **내 환율** / **지갑 환율** | 설명이 필요 없음. 화면에 이미 `100 JPY = 970원` 형태로 나오므로 "환율"이라는 말과 모양이 맞음 | 엄밀히는 환율이 아니라 평균 원가 |
| A2 | 환전 단가 / 지갑 단가 | 원가라는 성격이 정확함 | `단가`는 개당 가격 어감이라 환율 표시와 안 어울림 |
| A3 | 지갑 평단가 | 주식 `평단가`(총 매입금액÷총 수량)와 계산이 똑같아서, 아는 사람에겐 즉시 이해됨 | 주식 용어를 여행 앱에 들여오는 셈. 모르는 사람에겐 오히려 어려움 |

**A1 `내 환율`로 확정.** 정확한 이름을 붙이려다 어려워지는 것보다, 쉬운 이름을 붙이고
설명 문구에서 "이 지갑에 든 돈이 실제로 얼마에 온 건지"라고 풀어주는 편이 낫습니다.
설명할 자리는 이미 앱 안에 있습니다.

### 4-B. 홈 화면의 두 숫자 — **`내가 낸 돈` / `내 부담액`로 확정 (2026-08-07)**

원문은 `You fronted`(내가 그룹을 위해 지출한 총액)와 `Your share`(내가 실제로
먹고 쓴 몫)입니다. 이 둘의 차이가 곧 정산 금액이라 **헷갈리면 앱 전체가 무너집니다.**

| 안 | 낸 돈 | 내 몫 |
| --- | --- | --- |
| **B1 (추천)** | **내가 낸 돈** | **내 부담액** |
| B2 | 대신 낸 돈 | 내 몫 |

**B1로 확정.** `부담액`은 정산기 화면에서 실제로 쓰이는 말이고(`1인당 부담
금액`), `내 몫`은 조사해보니 어느 앱에서도 UI 라벨로 확인되지 않았습니다 — 말로는
자연스럽지만 라벨로는 근거가 없습니다.

### 4-C. 지출 취소 → **스위치로 변경 (2026-08-06 확정)**

원문은 `Cancel expense` / `Restore expense`. 처음에는 버튼 두 개의 이름만 바꾸려
했는데, 검토 중에 **단어가 아니라 화면이 문제**라는 결론이 났습니다.

**왜 바꾸나.** 한국어에서 "결제 취소"는 **환불**입니다. 그런데 이 기능은 돈을
돌려받는 게 아니라 **이미 쓴 돈을 정산 계산에서만 빼는 것**입니다. 기록은 피드에
회색으로 남고 "누가 뺐는지"까지 표시됩니다. `지출 취소`라고 쓰면 가게에서 결제를
취소한 것으로 읽힐 수 있고, 그러면 되돌리는 버튼의 이름도 따라서 이상해집니다.

**확정안.** 버튼 두 개 대신 **스위치 한 개**입니다.

| --- | --- |
| 라벨 | **정산에 포함** (기본 켜짐) |
| 도움말 | 끄면 기록은 남고 정산에서만 빠져요. |
| 끌 때 확인창 | 정산에서 뺄까요? / 아무도 이 금액을 주고받지 않게 돼요. 다시 켜면 그대로 돌아와요. |
| 확인창 버튼 | `닫기` · `빼기` |
| 피드 표시 | {name}님이 정산에서 뺀 지출 |

켤 때는 확인하지 않습니다. 끄는 쪽만 다른 사람의 정산 금액을 바꾸기 때문입니다 —
지금 코드에도 "잔액을 바꾸는 동작은 반드시 확인한다"는 규칙이 이미 있고, 되돌리는
동작은 그 규칙에 걸리지 않습니다.

**감수한 위험 하나.** 이 앱에는 이미 `개인 지출(다른 사람과 나누지 않음)`이
있어서, `정산에 포함`과 겹쳐 읽힐 수 있습니다. 실제로는 다릅니다 — 개인 지출은
**진짜 쓴 돈이라 내 지출 합계에는 들어가고** 남과만 안 나누는 것이고, 정산에서 뺀
지출은 **아무 데도 안 들어갑니다.** 위 도움말 문구가 이 차이를 드러내는 역할을
합니다.

**작업 비용.** 번역이 아니라 화면 변경입니다. `CancelExpenseForm.tsx`를 스위치로
바꾸고, 이 버튼을 눌러 검사하는 `e2e/wallet.spec.ts`도 같이 고쳐야 합니다.

### 4-D. 앱 이름과 한 줄 소개 (2026-08-07 확정)

**이름은 `FairSplit` 그대로입니다.** 원래 쓰려던 `splitmate`는 도메인 임자가 따로
있어서 못 썼고, 그래서 폴더·저장소 이름만 `splitmate`로 남아 있습니다. 이름은 다시
논의할 대상이 아닙니다.

| | |
| --- | --- |
| 원문 (영어) | Split group expenses fairly — at your own exchange rate. **유지** |
| **한국어** | **기록만 남기세요. 환율도 정산도 알아서 할게요.** |

**왜 "공정하게"를 뺐나.** 정산이라는 행위 자체가 공정해지려고 하는 일이라, 한국어로
옮기면 같은 말을 두 번 하게 됩니다. 대신 이 앱이 실제로 없애주는 두 가지 — **환율
씨름과 매번 하는 정산** — 을 앞세웠습니다. 사용자가 할 일은 기록뿐이고 나머지는
앱이 한다는 약속이 이 제품의 핵심입니다.

**영어는 왜 그대로 두나.** 영어의 `fairly`는 한국어의 "공정하게"와 사정이 다릅니다.
브랜드 이름 `FairSplit`을 되받는 말이라 제 역할이 있습니다. 한국어 문구는 그 이름을
짊어지지 않으므로 뺄 수 있습니다.

직역했다면 "그룹 지출을 공정하게 나누세요 — 당신만의 환율로"가 됐을 텐데,
`당신만의`는 전형적인 번역투입니다(§7).

### 4-E. 로딩 문구는 당분간 영어로 둡니다 (2026-08-07 확정)

한 번 한국어로 옮겨봤는데 읽어보니 어색해서, **번역을 되돌리고 영어를 그대로
둡니다.** 원문이 농담에 가까워서 뜻만 옮기면 죽고, 새로 쓰려면 번역이 아니라
창작이라 따로 시간을 들여야 합니다. 지금은 영어로 두는 편이 어색한 한국어보다
낫다는 판단입니다.

아래는 처음 검토했을 때의 메모입니다.

## 5. 조사(을/를·이/가) 규칙 — 안 지키면 화면이 깨집니다

한국어 조사는 앞 글자 받침에 따라 달라집니다. `철수가` / `민준이`, `1,000원을` /
`3달러를`. 그런데 변수 안에 무엇이 들어올지는 실행 전에 알 수 없습니다.

문구 473개 중 **101개가 변수를 품고 있고, 33개는 변수 바로 뒤에 글자가 붙습니다.**
그대로 옮기면 "**김민준가** 환전 기록을 반영했어요" 같은 문장이 실제 화면에 뜹니다.
번역투보다 훨씬 눈에 띄는 종류의 오류입니다.

라이브러리로 푸는 문제가 아니라 **문장 구조로 푸는 문제**입니다. 규칙 세 개입니다.

### 규칙 1. 사람 이름 뒤에는 반드시 `님`

`님`은 받침이 고정이라 뒤에 오는 조사가 항상 결정됩니다.

| | |
| --- | --- |
| 안 됨 | `{name}이 환전 기록을…` |
| 됨 | `{name}님이 환전 기록을…` |

이름이 들어가는 21개 문구가 이 한 줄로 해결되고, 덤으로 존댓말이 자연스러워집니다.

### 규칙 1-b. 안 변하는 조사는 붙여도 된다 — `에` · `에서` · `의`

받침에 따라 달라지는 건 `은/는`, `이/가`, `을/를`, `와/과`, `로/으로`뿐입니다.
**`에`, `에서`, `의`는 어떤 글자 뒤에서도 그대로**라 변수에 바로 붙여도 안전하고,
오히려 그래야 문장이 자연스러워집니다.

| 원문 | 한국어 |
| --- | --- |
| `Paid from {label}` | `{label}에서 결제` |
| `Add a top-up to {label}` | `{label}에 충전하기` |

### 규칙 1-c. 사용자가 지은 이름 뒤에 명사를 덧붙이지 않는다

지갑 이름은 사용자가 짓습니다. 그래서 `{label} 지갑에서`라고 쓰면 "카드 지갑"이라
이름 붙인 사람에게는 **"카드 지갑 지갑에서"**가 됩니다. 실제로 나온 버그입니다.

조사를 받쳐줄 명사가 필요해서 붙였던 건데, 규칙 1-b대로 `에/에서/의`를 쓰면
그 명사 자체가 필요 없어집니다.

### 규칙 2. 그 외 변수 뒤에는 조사를 두지 않는다

통화 코드(`JPY`), 지갑 이름(`{label}`), 금액(`{amount}`)은 `님`을 붙일 수 없으니
문장을 다시 짭니다.

| 원문 | 안 되는 번역 | 되는 번역 |
| --- | --- | --- |
| `Delete {label}?` | `{label}을 삭제할까요?` | `{label}, 삭제할까요?` |
| `Adds up to {amount}.` | `{amount}이 됩니다.` | `합계 {amount}` |
| `spent in {currency}` | `{currency}를 쓰는 곳` | `현지 통화는 {currency}` |

요령은 **변수를 문장 끝이나 괄호 안으로 밀어내는 것**입니다. 한국어는 어차피
`항목: 값` 형태를 자연스럽게 받아들입니다.

### 규칙 3. 복수형은 신경 쓸 것 없다

영어는 `1 member` / `2 members`로 갈라지지만 한국어는 안 갈라집니다.

| 원문 | 한국어 |
| --- | --- |
| `{count, plural, one {# member} other {# members}}` | `{count}명` |

해당하는 문구는 2개뿐이고, 둘 다 단순해집니다.

## 6. 숫자·날짜·금액

| 항목 | 처리 | 이유 |
| --- | --- | --- |
| 숫자 | `1,234` 그대로 | 한·영 표기가 동일 |
| 금액 | `1,234원` / `¥20,000` | 현재 방식 유지 |
| 날짜+시각 | `2026. 8. 1. 오후 4:41` | 영문 `Aug 1, 2026, 4:41 PM`에서 변경 |
| 짧은 날짜 | `8월 1일` | 영문 `Aug 1`에서 변경. 연도가 자명한 자리 |
| 상대 시각 | `3분 전` | 현재 `{ago} ago` 구조 유지 |

날짜만 바뀌고 숫자·금액은 손대지 않습니다.

처음에는 `2026년 8월 5일`로 적었지만, 실제로 만들어보니 한국어 `medium` 형식은
`2026. 8. 1.`입니다. 한국 앱에서 훨씬 흔한 표기이고 폰에서 줄바꿈도 나지 않아
그대로 씁니다 — 문서를 결과에 맞췄습니다.

시각만 나오는 자리(`12:03`)는 24시간 표기로 고정돼 있어 언어와 무관하게 같습니다.
그래서 `'en'`이 박힌 세 곳 중 **두 곳만** 고쳤습니다.

금액에 띄어쓰기를 넣지 않는 것(`1,234원`, `1,234 원` 아님)은 국립국어원이 밝힌
관례입니다 — 원래 맞춤법대로면 띄어야 하지만, 금액은 변조를 막으려고 붙여 쓰는
것이 관례로 굳었습니다.

## 9. 아직 못 정한 것

정직하게 남깁니다. 조사로 답이 안 나온 것들이라 진행하면서 정해야 합니다.

- **삭제 확인창의 실제 문구.** 토스가 "왼쪽은 닫기, 실행 버튼은 구체적으로"라는
  구조는 공개했지만, 한국 앱들의 실제 삭제 확인 문구는 화면 캡처가 검색에 안
  걸려서 확정 근거를 못 찾았습니다. `삭제할까요?`로 갑니다 — 규칙에는 맞지만
  "이게 업계 표준"이라고는 말씀드릴 수 없습니다.
- **로딩 문구 20개.** §4-E대로 다시 씁니다. 한국 앱의 장난스러운 로딩 문구는
  평판은 있는데 인용 가능한 실제 사례를 못 찾았습니다.
- **`{count}명` vs `{count}인`.** 멤버 수를 셀 때인데, 둘 다 자연스러워서
  화면에 넣어보고 정하는 게 빠릅니다.

## 10. 화면에서 잡은 것들 (2026-08-07, 실제 렌더링 확인)

| 증상 | 원인 | 처리 |

| `JPY 쓰는 곳으로 가시나요?` | 한국어는 통화 코드가 아니라 나라를 부름 | `일본 가시나요?` — `Intl.DisplayNames`로 나라 이름을 냄 |
| 나라 선택 목록이 `Japan` | 목록 데이터가 영문 이름만 가짐 | 같은 방법으로 `일본`, 정렬도 한국어 기준으로 |
| `카드 지갑 지갑에서` | 사용자가 지은 이름 뒤에 명사를 덧붙임 | 규칙 1-c |
| `나머지는 어디서 나왔나 / 요?` | 브라우저가 한글을 글자 단위로 끊음 | `word-break: keep-all` 전역 적용 |
| `+ 추가` 버튼의 글자 | 아이콘이 이미 같은 말을 함 | 아이콘만 남기고 글자는 접근성 이름으로 |

`word-break: keep-all`은 CJK에만 적용되는 속성이라 영어 화면에는 영향이 없습니다.
긴 URL이 넘치지 않도록 `overflow-wrap: break-word`를 함께 둡니다.

**아직 영어인 것:** 도시 이름(Tokyo, Osaka…). `Intl`이 도시는 다루지 않아 직접
목록을 만들어야 하고, 나라만큼 급하지 않아 남겨뒀습니다.
